Features

Everything you need on the bus.

From a quick look at the values to the report you hand over to your client.

Overview & charts

Every group address as a card with its current value and a mini history. Charts with up to eight addresses, one axis per unit.

Telegrams & bus monitor

Every telegram live, plus raw frames with ACK/NAK and bus load. Send like the ETS group monitor, delayed and cyclic too.

Health

Reads status addresses, reports devices that went silent and checks cycles, values, datapoint types and bus quality. With a PDF report.

Commissioning

A checklist of all status addresses, answers are checked off automatically. Finish with a PDF report including a signature field.

Objects, devices & topology

Rooms and objects from your project, actuators drawn as DIN-rail devices with channel LEDs, lines and couplers. The map shows who talks to whom.

KNX Secure & routing

Tunnel over UDP or TCP, routing via multicast, KNX IP Secure and Data Secure with the keyring from ETS.

Also included

  • Find programming mode, check addresses, scan lines
  • Recordings with real-time replay, trigger recordings
  • Long-term history and statistics with an activity heatmap
  • Compare the ETS project with bus traffic
  • Export as PDF, CSV and for ETS
  • Alarm notifications
  • Diagnostics bundle for bug reports, without names or values
  • Demo house to try it without a KNX system
  • German and English

Install the add-on

  1. In Home Assistant, open Settings → Add-ons → Add-on Store.
  2. Choose ⋮ → Repositories in the top right and add this URL:
    Repository URLhttps://github.com/regetskcob/KNX-Monitor
  3. Install KNX Monitor, start it and enable Show in sidebar.
Privacy

Everything stays local.

KNX Monitor only talks to the KNX interface on your own network. No server, no account, no analytics. Your project, telegrams and Secure keys stay with you; your ETS project password is never stored.

FAQ

Frequently asked questions

Can I try the app without a KNX system?

Yes. “Try the demo without a KNX system” on the start screen opens a sample house with a project and live values. Your own project stays untouched.

Which KNX interfaces are supported?

Any KNXnet/IP interface or IP router, for example a Gira X1. Tunnelling works over UDP or TCP; with an IP router you can also use routing, which needs no tunnel (not yet on iPhone and iPad, where multicast needs approval from Apple). USB and serial interfaces are not supported.

Why can't I connect although the interface is reachable?

IP interfaces only offer a few tunnels, often four or fewer. If visualisation, ETS or other apps use all of them, the interface refuses. Free a tunnel, configure an additional one in ETS, or use routing.

Is KNX Secure supported?

Yes: KNX IP Secure for the tunnel and KNX Data Secure for encrypted group addresses. Import the keyring (.knxkeys) from ETS. The keys are kept in your device’s keychain. If something doesn’t work with your interface, please report it on GitHub.

Do I need an ETS project?

No, the bus monitor works without one. With a project you get names, datapoint types, rooms and better checks. The password of a protected project is only used during import and is not stored.

How do I get the desktop version?

Mac, Windows and Linux do everything the iPad app does. Downloads are in the GitHub release. They are not signed yet: on a Mac, open the app with right-click → Open the first time; on Windows, SmartScreen may warn.

What do I need for the KNX box?

A Raspberry Pi 4 or 5 with a real-time clock (Pi 5: battery, Pi 4: RTC module) so timestamps stay correct without internet, and ideally a USB SSD. The ready-made image to build your own is in the GitHub releases; it is a first preview.
