Features

Everything you need on the bus. Nothing you don't.

From a quick look at the values to the report you hand over to your client.

Live overview

Values per group address as cards with mini charts, averages and step lines for switching states. Grouped by measurement type and ETS main group, with favourites you can pin.

Objects

Group addresses are combined into rooms and objects, with commands and feedbacks side by side. Works with many naming schemes, English ones included.

Telegrams & bus monitor

Every telegram live, plus raw frames with ACK/NAK, repeats and bus load. Filtering and export included.

Health

Re-reads known status addresses, compares with the last run and reports devices that went silent. Cycle watchdog, plausibility, DPT consistency per sender and bus quality, with history and a PDF report.

Commissioning

Read all status addresses, check off answers automatically, mark the rest as OK or issue with a note. Finish with a PDF report including a signature field.

Topology & communication map

Lines, couplers, hop count, cross-line traffic and tunnel addresses. The explorer shows who talks to whom.

Diagnostics

Find the device in programming mode, check individual addresses, scan a line and read device info.

And more

Project comparison, statistics, recordings and long-term history, trigger recordings, export as PDF, CSV and for ETS, and alarm notifications.

Privacy

Everything stays local.

KNX Monitor only talks to the KNX interface on your own network. There is no server, no account, no analytics and no tracking. Your project, telegrams and recordings stay on your device, and your ETS project password is never stored.

Home Assistant

Also runs as a Home Assistant add-on.

The add-on opens KNX Monitor right in the Home Assistant sidebar (ingress) and runs on the host you already have. No extra hardware, no extra port.

  1. In Home Assistant, open Settings → Add-ons → Add-on Store.
  2. Choose ⋮ → Repositories in the top right and add this URL:
    Repository URLhttps://github.com/regetskcob/KNX-Monitor
  3. Install KNX Monitor, start it and enable Show in sidebar.
FAQ

Frequently asked questions

Can I try the app without a KNX system?

Yes. “Try the demo without a KNX system” on the start screen opens a made-up sample house with a project and live values. Your own project stays untouched and the demo stores nothing.

Which KNX interfaces are supported?

Any KNXnet/IP interface or IP router with tunnelling, for example a Gira X1 or an IP interface or router from another manufacturer. USB and serial interfaces are not supported.

Why can't I connect although the interface is reachable?

IP interfaces only offer a few tunnels, often four or fewer. If visualisation, ETS or other apps use all of them, the interface refuses further connections. Free a tunnel or configure an additional one in ETS.

Is my ETS project password stored?

No. The password is only used to decrypt the project during import and is discarded afterwards. Only the names, datapoint types and structure read from the project are stored, locally on your device.

Is KNX Secure supported?

Not yet. Secure tunnelling and encrypted group communication (KNX Data Secure) are currently not supported. Unencrypted telegrams on the same bus are shown as usual. If you need KNX Secure, vote with 👍 on GitHub – it helps us prioritise.

Is KNXnet/IP routing (multicast) supported?

Not yet. With a KNX IP router, routing would let you listen to the bus without occupying a tunnel. There is no IP router available for testing yet, so it isn’t planned. If you would use routing, vote with 👍 on GitHub – and get in touch if you can test with your router.

Do I need an ETS project?

No, the bus monitor works without one. With a project you get names, datapoint types, rooms and more meaningful checks.
